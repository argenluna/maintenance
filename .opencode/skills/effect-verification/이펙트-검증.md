- **⚠️ 2026-11-27 사용자 지적으로 재검토**: 원곡 기준 개선이 거의 없는데(Δ0.003) 승인본 기준으로만 채택한 것은 원칙 위반. 승인본은 목표가 아니라 회귀 확인용 보조일 뿐이다. 이 판단을 일반 원칙(아래 교훈 14)으로 승격시킨 것이 잘못이었다.

11. **광대역 밴드 평균은 좁은 스파이크와 구멍을 상쇄해 숨긴다.** 고역은 최소 16-18k / 18-22k 로 쪼개서 볼 것.

- `assemble.py`의 성부별 전역 RMS 복원(`gain=orig_rms/conv_rms`, 78~82행)은
  각 성부의 **총 에너지**만 맞춘다. 시간대별 리드/화음 대비는 복원 못 함.
- `fx_transfer.py`의 env 전이(341~350행)가 `g=1+1.2*tanh((ratio-1)/1.2)` 로
  압축하고 `[0.4,2.5]` 로 클립 → 리드 구간 부스트가 제한됨.
- 이펙트가 **성부별**로 적용되므로 합산 후 **버스 레벨** 다이내믹은
  그 누구도 직접 맞추지 않았다.

### 원인 2 — 이펙트 누락 + 검증 오탐
- `auto_fx.py` 85행 `use["pitch"] = False` 가 무조건. pyin 궤적 confidence **1.0**,
  124점 곡선이 감지됐지만 **전혀 적용 안 됨**. (⚠️ 단, RVC `pitch=0`이 입력 f0를
  이미 그대로 전사하므로 재적용은 이중 보정 — 의도적 off로 유지하고 문서화만.)
- `gate` 0.28/0.19(<0.45), `echo` 0.0(탭 없음) → 이건 신뢰도 기준 정당한 off.
- 고역 손실: eight 밴드4/5 **−2.7/−2.48dB**, karma **−3.98/−3.29dB**,
  `hf_db=−2.06`. 그런데 `TH`가 `band_loss_db −6`, `hf_loss_db −7`,
  `dyn_floor 0.70` 이라 **전부 pass**. eight `dynamic_ratio 0.813`인데도
  `under_application=0` → **검증기가 실제 결함을 놓친 거짓 pass**.

### 코드 수정 (2026-11-25)
- `assemble.py`: `_restore_bus_envelope()` 신규. 합산된 보컬버스의 10ms 엔벨로프를
  원본 `_sep/vocal_bus.wav` 대비 **상대 매칭**(3프레임+5프레임 평활, 게인 0.5~3 제한).
  레인 합산 직후, 반주 합산 전에 적용. 리포트에 `bus_envelope` 필드 추가.
- `bus_pipeline.py`: manifest에 `vocal_bus_ref` / `bus_env_strength` 추가.
- `fx_verify.py` TH 강화: `band_loss_db −6→−2.5`, `hf_loss_db −7→−2.0`,
  `dyn_floor 0.70→0.88`. (전부 원곡 대비 상대값, 절대 임계 아님)
- ⚠️ 체인 순서 변경: `effect(성부별) → mix(성부합산) → **버스 엔벨로프 복원** →
  반주합산 → level match → verification`.

### 수정 효과 실측 (원본 풀믹스 기준, eight)
| 항목 | 원본 | 기존 완성본 | 수정 본 |
|---|---|---|---|
| 리드 구간 음량 | 0.4103 | 0.653배 | **0.963배** |
| 화음 구간 음량 | 0.1728 | 0.908배 | **1.004배** |
| 리드/화음 대비 | 2.37 | 1.71 | **2.28** |

→ 리드 35% 부족이 해소됨. 단, `fx_verify`의 `dynamic_ratio`는 crest(peak/rms)
비율이라 이 대비를 못 잡고 0.81로 그대로였다. → `assemble.py`에
`vocal_balance`(원본 보컬버스 상위10%/하위30% 구간의 풀믹스 대비) 지표를
추가해 리포트에 기록하도록 함. **crest 기반 dynamic_ratio를 밸런스 근거로
쓰지 말 것.**

### 교훈
1. **성부별 RMS 매칭 ≠ 버스 다이내믹 복원.** 리드/화음 대비는 반드시 합산 후
   버스 레벨에서 원곡 대비 상대 엔벨로프로 맞출 것.
2. 검증 임계가 느슨하면 "pass"가 품질 보증이 아니다. 사용자가 들은 결함을
   검증기가 잡지 못하면 **임계를 고치지 결과를 믿지 말 것**.
3. 이펙트 "skipped"는 전부 누락이 아니다. 감지 신뢰도/중복 보정 여부를
   구분해서 기록해야 한다 (pitch=의도적 off, gate/echo=신뢰도 미달, tail=적용됨).

## 2026-11-24 (1차) — effect verification 스킬 신규 등록 + 5축 검증 + 피드백 루프

### 사용자 요구
- 순서 수정: `unmix → RVC → effect → mix → effect verification` (새 스킬).
- 검증할 부작용: (1) 이펙트 중첩/과적용, (2) 노래 깨짐, (3) 음색 죽음,
  (4) 이펙트에 묻혀 보컬 묻힘. (5) 반대로 너무 약함/밋밋하면 강도를 더 주는 기능.

### 구현 (`fx_verify.py`)
| 함수 | 역할 |
|---|---|
| `analyze(final, orig, sr)` | 5축 진단. 밴드 dB(8초 Welch×4), 고역 잔향 배율, 엔벨로프 변조/std, 좌우상관, 보컬대역(300~3.5k), crest 다이내믹, 발성구간 무음률, 상관. |
| `apply_local_fix()` | 고역 tilt 부스트(≤+4dB), 과부스트 밴드 peaking 감쇠, 딸깍 클립, 소프트 리미터. 6초 청크. |
| `verify()` | analyze → 로컬 보정 → `(out, report)`. `strength_scale`(effect 재조립 배율) 포함. |

### 판정/출력
- `verdict`: `pass` / `adjusted` / `rerun_needed`.
- `scores`: 5축 각각 0~1 (0=정상).
- `issues`: `[{axis, severity, detail, fix}]`.
- `strength_scale`: `{env, onset, tone, tail, pan, gate, echo}` 배율.
  예) 과적용 감지 시 `{tone:0.55, tail:0.5, gate:0.3}`.

### 피드백 루프 (`assemble.py`)
```
_build_mix(scale) → match_level → V.verify → pass? 종료
                                   └ 문제? strength_scale 누적(0.4~2.2 클립)
                                            → auto_fx(strength_scale=...) 재조립 (최대 2회)
```
- `auto_fx.py`에 `strength_scale` 인자 추가 → `plan["strengths"]`에 곱한 뒤 적용.
- 출력 기본 `FINAL_verified.wav` + `_report.json` (`verification`, `feedback_rounds` 포함).

### 버그/교훈
1. **딸깍 절대 임계 오탐**: 랜덤 노이즈 테스트에서 Same-signal이 `adjusted`로 판정.
   → `최종 clicks - 원곡 clicks` 상대 비교로 수정. 동일 신호는 `pass` 확인.
2. 모든 비교는 원곡 대비 **상대 dB/배율**만 사용 (곡마다 절대 기준 다름).

### 검증
- 동일 신호 mono/stereo: `pass`, scores 전부 0, 로컬 보정 안 함. ✅
- 합성 부작용(과부스트+노이즈+앞 0.5초 무음): `rerun_needed`,
  over 1.0 / corruption 1.0, tail 0.5·gate 0.3·tone 0.55 배율 생성, 로컬 보정 적용. ✅
- 실제 T-ara 최종본(`FINAL_effect_skill.wav`): `pass`,
  밴드오차 -2.91~+0.5dB, 고역 -1.97dB, 잔향 0.80배, 변조 1.006배,
  상관 0.965, 보컬 0.909배, 피크 0.984 → **이슈 0건**. ✅

## 6차 (2026-11-26) — 밸런스 지표 연동

사용자: "레인이 어떤 파트인지 검출하는 것도 중요하지만 **레인 간·파트 간
밸런스를 맞추는 것도 굉장히 중요해**."

### 구현
- `fx_verify._vocal_balance(final, original, manifest, sr)` 추가 →
  `analyze()["metrics"]["vocal_balance"]`에 들어간다. manifest의
  `vocal_bus_ref`를 열어 원본 보컬버스 상위 10%(리드)/하위 30%(화음) 구간을
  고르고, 그 구간의 **원본 풀믹스 대비** 에너지를 최종본과 비교.
  0.1초 프레임, 곡 내부 상대값만 사용, 절대 임계 없음.
- `rep["balance_ok"]`: 리드/화음 비가 각 0.75~1.33이면 True.
  ⚠️ **5축 issue/verdict에는 넣지 않는다** — `strength_scale`(effect 강도)과
  섞이면 잘못된 재조립 피드백이 걸리기 때문. 밸런스는 mix 단계에서 고친다.
- `assemble.py`는 `vrep["metrics"]["vocal_balance"]`를 매 라운드 출력하고,
  이탈 시 `⚠️ 밸런스 이탈`을 표시한다.
- 실제 밸런스 보정은 `lane_balance.balance_lanes()`가 mix 직전에 수행
  (역할별 전역 레벨 + 프레임 상대 게인). 자세한 건 `unmixing/레인-검출기.md`.

### 검증
- 합성 2레인(리드 eff를 orig의 0.5배로 누출): 역할 게인 2.0 적용,
  원본 RMS 0.431 → 최종 0.430, 역할 대비 5.0 → 5.0. ✅
- Cry Cry `_cry_out_pa`: `orig_contrast 2.34 → final_contrast 2.226`,
  `lead_ratio 0.97 / harm_ratio 1.019` → `balance_ok=True`. ✅
- ⚠️ crest 기반 `dynamic_ratio`는 원곡 클리핑 시 오탐 → 밸런스 근거로 쓰지 않는다.
