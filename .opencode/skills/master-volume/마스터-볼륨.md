### 원인 (실측)
v1 `master_unify.py`가 44.1kHz에서 `A.soft_limit`(tanh)을 **샘플 단위 웨이브셰이핑**으로 걸었다.
게인을 올리면서 peak를 동시에 낮추는 이중 되먹임이 리미터를 계속 세게 몰아붙였다.

| 곡 | crest 전→후 | 16kHz↑ 전→후 | 잔차 |
|---|---:|---:|---:|
| 홀씨 | 3.76→2.56 | ×1 → **×19.2** | 8.9% |

하모닉이 나이퀴스트 아래로 접혀 고역 쓰레기가 생기고 피크가 평평해져
"찢어지고 깨지는" 소리가 났다. 4곡 전부 같은 코드를 지났으므로 전곡 발생.

### 대안 실험 (`exp_master_options.py`, `exp_loudnorm_targets.py`)
- `loudnorm` 2-pass: 깨지진 않으나 곡별 I −8.82~−10.18 (1.36dB 편차) → 음량 통일 실패
- `gain_only`: I −9는 맞지만 TP +1.78 → 클리핑
- `alimiter`: TP +1.18, 재정규화 문제
- tanh 4x 오버샘플(v2): HF ×10.2로 개선되나 여전히 잔존

### 최종 v3 (`master_unify_v3.py` → `master_unify.py` 로 덮어씀)
- 4x 오버샘플 + 2ms 롤링 최대 엔벨로프 + 30ms `minimum_filter1d` 룩어헤드/릴리즈
- **파형을 건드리지 않고 게인만 움직임** → 하모닉/별칭 없음
- 내부 게인 되먹임(I→−9) + 외부 ceiling 되먹임(TP≤−1)

## 2026-11-25 (1차) — 스킬 신설 / 4곡 일괄 통일

### 사용자 요청
> "모든 검증이 끝났을 때 master volume이라는 스킬을 넣어서 모두 음량을 일괄로 맞춰.
> 노래 바뀔 때마다 음량조절을 할 순 없잖아"

### 체인 위치
```
unmix → RVC → effect → mix → effect-verification 1차 → supplement-effect
 → effect-verification 2차 → safety gate → master-volume → completesong
```
검증 전에 음량을 건드리면 밴드/다이내믹 지표가 오염된다. **검증 후 한 번만.**

### 실패한 접근 (기록)
- `master_candidate.py`의 `loudnorm linear=true`는 피크 제한 때문에
  목표 I를 못 맞춤: 홀씨 −9.48, day by day −9.83 LUFS.
- ffmpeg `alimiter=limit=0.891:level=disabled`는 출력을 재정규화해
  TP가 **+0.37 dBFS**로 튀었다. `level=disabled`가 먹지 않음.
- numpy `soft_limit`으로 sample peak 0.891에 묶어도 mp3 인코딩 오버슈트로
  TP +0.31 → +0.37. **외부 루프에서 peak 자체를 낮춰야 함.**

### 최종 구현 (`master_unify.py`)
1. `A.soft_limit(y/peak, knee=0.95)*peak`로 피크를 묶는다.
2. 내부 루프: 게인 되먹임으로 I → −9 LUFS (허용 ±0.07).
3. 외부 루프(7회): `peak *= 10^((-1.10 - measured_TP)/20)` 로
   mp3 오버슈트를 보상해 TP ≤ −0.92 dBTP로 수렴.
4. 320k / 44.1k / stereo mp3.

전부 −9 LUFS ±0.07, TP ≤ −1 이내. 곡 바꿀 때 볼륨 조정 불필요.
