자동 유지보수 (Windows) — 사용 방법    [v1.14.5 / 2026-11-21]
Auto Maintenance for Windows — How to Use  [v1.14.5 / 2026-11-21]
自動メンテナンス（Windows）｜使い方ガイド 🪟🔧✨
=====================================

※ 컴퓨터를 하나도 모르는 분은 먼저 "newbie.txt" 를 읽어보세요.
   이 파일은 39개 검사를 레고·집·주방 비유로 하나씩 풀어서 설명합니다.

【버전 확인】 내가 받은 파일이 최신인지 확인하는 방법
  - 이 파일 맨 윗줄에 버전이 적혀 있습니다(예: v1.14.5).
  - 설치 폴더의 "VERSION" 파일을 메모장으로 열어도 같은 버전이 보입니다.
  - 점검 결과 txt 파일에도 "버전: v1.14.5 (2026-11-21)" 줄이 있습니다(영어권은 "Version: ...").
  - 받은 ZIP 파일 이름이 "AutoMaintenance_v1.14.5_20261121.zip" 처럼 버전+날짜로 되어 있습니다.
  - 버전 숫자가 더 큰 파일이 최신입니다. 예전 ZIP(v1.5.0 이하)을 쓰고 있다면 새 ZIP 으로 바꾸세요.
  - 자동 업데이트는 옛 폴더를 지우지 않고 옆에 남깁니다(롤백용). 예약 작업과 바로가기는 새 폴더만 가리킵니다.
    옛 폴더 안의 프로그램은 직접 실행하지 마세요. 새 버전이 며칠간 정상이면 옛 폴더는 직접 지워도 됩니다.

【설치】 1회만
  1. 압축을 **이 프로그램만 쓰는 전용 폴더에 완전히** 풀어 둡니다(예: H:\AutoMaintenance_v1.14.5).
     압축 파일 안에서 바로 실행하지 마시고, 공용 폴더·공유 드라이브·C:\ 루트는 피하세요.
     예약 작업이 관리자 권한으로 이 폴더의 스크립트를 실행하므로, 다른 계정이나 외부 프로그램이
     이 폴더의 .ps1/.json 파일을 수정할 수 없도록 나만 쓰는 개인 폴더에 두세요.
     받는 곳은 공식 릴리즈(https://github.com/argenluna/maintenance/releases)만 사용하세요.
     압축을 푼 뒤 "차단됨" 표시나 Defender 경고가 뜨면 출처가 위 주소인지 확인하고 차단 해제하세요.
     출처를 모르는 파일이면 실행하지 마세요.
  2. "install.cmd" 를 더블클릭합니다.
  3. 파란 확인 창이 뜨면 "예" 를 누릅니다.
  4. 첫 점검이 끝날 때까지 기다립니다(약 1~10분, PC 상태에 따라 다릅니다).
  5. "Enter 키를 누르면 닫힙니다" → Enter.

  ※ "install.ps1" 을 더블클릭하면 메모장으로 열립니다. 반드시 "install.cmd" 를 쓰세요.

【평소】 아무것도 하지 않아도 됩니다.
  - PC가 켜져 있으면 6일에 한 번 자동으로 점검합니다.
  - 결과는 바탕화면의 "자동유지보수_날짜시간.txt" 파일입니다(영어권은 "auto-maintenance_날짜시간.txt"이고 내용도 영어). 맨 위 3줄만 보면 됩니다.

【바탕화면 바로가기 이름 — 윈도우 언어에 따라 달라집니다】 (v1.6.0, 이름 변경 v1.7.0)
  - 윈도우 시스템 언어가 한국어이면 한글 이름과 한글 결과 txt 를 그대로 씁니다.
      · 자동 유지보수 점검        = 지금 바로 점검
      · 자동 유지보수 제거        = 자동 점검 끄기
      · 자동 유지보수 피드백      = 의견 보내기
  - 한국어가 아니면(영어 등) 영어 이름과 영어 결과 txt 를 씁니다.
      · auto-maintenance          = 지금 바로 점검
      · remove maintenance        = 자동 점검 끄기
      · feedback maintenance      = 의견 보내기
      · 결과 파일: auto-maintenance_날짜시간.txt (실패 시 auto-maintenance_failed_날짜시간.txt)
      · 결과 보관 폴더: maintenance results
  - 언어를 나중에 바꾸고 다시 설치하면 예전 언어의 바로가기는 모두 정리됩니다.
  - 피드백 자체검사(SelfTest) 결과, 피드백 상태 파일, 피드백 창 메시지도 같은 언어로 나옵니다.

【바탕화면 결과 파일 정리】 (v1.4.0)
  - 결과 파일이 4개 이상 쌓이면 바탕화면에 "자동점검결과" 폴더를 만들어 그 안으로 옮깁니다.
  - 최신 것까지 전부 폴더로 옮기고, 바탕화면에는 이번에 새로 만든 결과 1개만 남습니다.
  - 지우는 것이 아니라 옮기는 것입니다. 옮긴 파일 목록은 결과 txt 의 [바탕화면 정리] 줄에 남습니다.
  - 창(콘솔)에도 "지난 결과 파일 N개를 자동점검결과 폴더로 옮겼습니다" 라고 표시됩니다.

【3개월 지난 결과 파일은 자동으로 지웁니다】 (v1.4.0)
  - 이 프로그램이 만든 결과 txt(자동유지보수_*.txt, MaintenanceReport_*.txt) 중
    마지막으로 쓴 날짜가 3개월(90일) 이상 지난 파일은 묻지 않고 자동으로 지웁니다.
  - 내가 만든 다른 파일(사진·문서 등)은 이름이 달라서 절대 지우지 않습니다.
  - 지운 파일의 위치·날짜·크기는 결과 txt 의 [오래된 결과 파일 자동 삭제] 줄에 남습니다.
  - 자동 삭제를 끄고 싶으면 설치 폴더\Simple maintenance\config.json 의
    "resultRetentionDays": 90 값을 0 으로 바꾸면 됩니다.

【오래된 드라이버 정리 — 30일에 한 번, 삭제는 y 확인 후에만】 (v1.13.0)
  - "새 버전이 이미 설치되어 있는데 옛날 버전이 남아 있는" 드라이버를 찾습니다.
    인터넷에서 최신 버전을 찾거나 드라이버를 자동 설치하지는 않습니다.
    같은 회사·장치 종류·INF 파일끼리 버전을 비교해서 로컬 저장소 안에서만 판단합니다.
  - 현재 사용 중인 드라이버, 컴퓨터가 켜질 때 필요한 드라이버(부팅/키보드/디스크 등)는
    후보에서 아예 제외합니다.
  - **30일에 한 번**만 확인합니다(이 프로그램에서 가장 긴 간격). 드라이버 목록은 거의 안 바뀝니다.
  - 점검 결과 txt 에 이렇게 적힙니다:
      [오래된 드라이버] 새 버전이 있음에도 남아 있는 이전 드라이버 2개
        · oem3.inf [장치: ACME Gigabit Ethernet] — ... [목록]  (oem 번호만이 아니라 장치 이름도 함께 표시)
        삭제: 1개 / 삭제되지 않음: 1개 — 확인해보세요. 직접 실행하여 삭제 질문에 y를 누르면 삭제됩니다. (이유도 함께)
  - **지우기 전에 반드시 물어봅니다.** "지금 점검"에서 y 를 누를 때만 지우고,
    n/Enter 를 누르면 아무것도 지우지 않습니다. 예약 자동 점검에서는 물어볼 사람이 없으므로
    목록만 보여주고 절대 지우지 않습니다.
  - 끄고 싶으면 설치 폴더\Simple maintenance\config.json 의
    "oldDriverCleanup": true 를 false 로 바꾸면 됩니다.
    감지 간격을 바꾸려면 "oldDriverCheckDays": 30 값을 조정하세요(0 이하면 매 실행).

【자동 점검은 창이 보일 때도, 안 보일 때도 있습니다】 (v1.3.0)
  - 자리를 비운 사이(5분 이상 마우스/키보드를 안 건드림)에 자동 점검이 돌면 검은 창이 떠서
    진행 상황이 보입니다. 창이 떠 있어도 그냥 두면 됩니다(닫지 않아도 알아서 끝납니다).
  - PC를 쓰고 있을 때 자동 점검이 돌면 창이 아예 생기지 않습니다(헤드리스).
    이때도 결과 파일·로그는 똑같이 남으므로 나중에 바탕화면 파일만 보면 됩니다.
  - "지금 점검"을 직접 누르면 항상 창이 보입니다.

【지금 바로 점검】 바탕화면의 "자동 유지보수 점검" 더블클릭
【자동 점검 끄기】 바탕화면의 "자동 유지보수 제거"(영어권: "remove maintenance") 더블클릭 (기록은 남습니다)

【점검 창이 사라지거나 결과 메모장이 안 보일 때】
  - "지금 점검" 을 누르면 검은 창이 떠서 점검이 끝날 때까지 그대로 있습니다(정상).
    창이 잠깐 보이다가 사라지면 예전 버전입니다 → 새 ZIP 으로 다시 설치하세요.
  - 결과 메모장은 항상 "내 바탕화면" 에 생깁니다. 파일 이름은 자동유지보수_날짜_시간.txt 입니다
    (영어권은 auto-maintenance_날짜_시간.txt이고 내용도 영어입니다).
  - 점검이 중간에 실패하면 바탕화면에 아래 파일이 대신 생깁니다. 이 파일을 열어 보세요.
      · 자동유지보수_실패_날짜_시간.txt  → 오류 내용과 로그 위치가 적혀 있습니다.
      · 자동유지보수_안내_날짜_시간.txt  → 점검이 시작되지 못한 이유(백신 차단/중복 실행 등)
  - 그래도 파일이 없으면 아래 두 로그를 보내 주세요(원인을 확인할 수 있습니다).
      · 설치 폴더\logs\runner-날짜.log
      · 설치 폴더\Simple maintenance\logs\maintain-날짜.log
  - 위 로그가 없으면 "설치 폴더\logs\console-날짜.log" 도 보내 주세요(창 없는 자동 점검 기록).

【설치 폴더를 지우지 마세요】
  예약 작업이 이 폴더의 스크립트를 실행합니다. 폴더를 옮기거나 지우면 자동 점검이 멈춥니다.
  폴더를 옮겼다면 "install.cmd" 를 다시 실행하세요.

【지우기 전에 꼭 물어봅니다 — 단계마다 A / Y / N】 (v1.14.5)
  - 휴지통(30일 지난 것), 브라우저 캐시(30일 지난 것), 임시 파일처럼 "지워도 되는 것"만 대상입니다.
  - 지울 파일이 있는 단계마다 목록과 용량을 보여주고 이렇게 묻습니다.
    "A = 언제나 삭제(설정에 기억) / Y = 현재만 삭제 / N 또는 Enter = 거부"
  - A 를 누르면 지금 지우고, 그 항목을 앞으로도 자동으로 지우도록 설정에 기억합니다.
    (다음 실행부터는 그 단계에서 묻지 않고 지웁니다. 예약 실행에서도 지웁니다.)
  - Y 를 누르면 이번 실행에서만 지우고 설정은 바뀌지 않습니다. (다음 실행에 다시 묻습니다.)
  - N 또는 Enter 를 누르면 아무것도 지우지 않습니다. (기본값)
  - A 로 기억한 항목을 되돌리려면 config.json 의 tempAutoDelete / browserCacheAutoDelete /
    recycleAutoDelete 값을 false 로 바꾸세요.
  - 자동 점검(6일에 한 번)은 물어볼 사람이 없으므로, A 로 기억하지 않은 항목은 아무것도 지우지
    않고 "보류"로만 기록합니다. 다음에 "지금 점검"을 실행하면 그때 목록을 보여주고 물어봅니다.
  - 지운 목록과 보류한 목록은 결과 txt 파일의 [삭제 전 확인 목록] 에 그대로 남습니다.
    폴더 이름까지 전부 남기므로 "어느 만화 폴더의 1.jpg" 인지 구분할 수 있습니다.
    A(설정에 기억된 자동 삭제)로 지웠는지, Y(이번만)로 지웠는지도 함께 적힙니다.
  - 다만 이 프로그램이 만든 결과 txt 중 3개월(90일) 지난 파일은 위 질문과 상관없이 자동으로 지웁니다
    (위 【3개월 지난 결과 파일은 자동으로 지웁니다】 참고).
  - 실제로 지운 파일은 Simple maintenance\logs\deleted-날짜-시각.txt 파일에도 남습니다(30일 보관).
    나중에 복구 프로그램(Recuva, PhotoRec 등)에 그대로 붙여넣어 찾을 수 있습니다.
  - 디스크가 아무리 부족해도(100MB 만 남아도) 컴퓨터가 알아서 지우지 않습니다.
    "지금 C 드라이브 여유 공간은 0.1GB 입니다. / 현재 용량으로는 디스크 속도나 이용에 문제가
    있을 수 있습니다. / 용량이 이만큼 남았으니 오래된 파일부터 삭제합니다. / 필요한 자료가
    있으시면 백업을 하세요." 라고 알려준 뒤 A 또는 Y 를 눌러야만 지웁니다.
  - 디스크가 "부족하다"고 판단하는 기준은 일괄 100GB 가 아니라 그 드라이브 용량의 10% 입니다.
    (예: 1.86TB 드라이브는 186GB, 4TB 드라이브는 400GB, 64GB USB 는 6.4GB)
    이 기준보다 많이 남아 있으면 "부족합니다" 라고 하지 않습니다. 남은 용량이 5GB 미만처럼
    정말 위험할 때만 "디스크 속도나 이용에 문제가 있을 수 있습니다" 라는 경고가 나옵니다.

【임시 파일 정리는 이렇게 안전하게 합니다】
  - 드라이브 전체(I:\ 등)나 사진/문서/바탕화면/다운로드 폴더는 절대 지우지 않습니다.
  - 이름이 Temp/Tmp/Cache 인 폴더, 또는 Windows·AppData 의 Temp 폴더만 대상입니다.
  - 최근 1일 안에 만들거나 고친 파일은 지우지 않습니다. (작업 중인 파일 보호)
  - 한 번에 최대 5GB 까지만 지웁니다(그 이상은 지우지 않습니다).
  - 공간을 채우려고 추가로 더 지우지 않습니다. 목록을 보여주고 y 를 눌렀을 때 그 목록만 지웁니다.
  - 공간이 부족한 그 드라이브 안의 임시 폴더만 정리합니다(다른 드라이브 때문에 엉뚱한 곳을 지우지 않음).
  - 임시 폴더 안의 바로가기(링크) 폴더는 따라가지 않습니다. 링크 너머의 다른 드라이브 자료는 건드리지 않습니다.

【자동으로 하는 일 (안전하고 되돌릴 수 있는 것만)】
  - 임시 파일/오래된 로그 정리, 디스크·메모리·배터리·드라이버 상태 점검
  - Windows 업데이트 캐시 정리, 복원 지점 생성, 주요 서비스 상태 확인
  - 광고/추천 문구 줄이기(설정만 변경, 되돌리기 가능)
  - 네트워크 우선순위 정리(가장 빠른 유선 회선을 1순위로)

【자동으로 하지 않는 일】
  - 프로그램 제거, 서드파티 업데이터 중지
  - 사용자 문서·사진·작업 파일 삭제 (위의 임시/캐시/휴지통 정리 외에는 손대지 않습니다)
  - 광고 도메인 차단(hosts/DNS)은 기본 꺼짐 — 켜려면 설정 파일에서 직접 켜야 합니다.
    켜더라도 100% 차단은 아니며, 일부 사이트가 느려지거나 안 열릴 수 있습니다.

【의견 보내기 — GitHub 자동 업로드】 (v1.5.0, 언어 대응 v1.6.0, 동봉 토큰 v1.14.5)
  - 바탕화면의 "자동 유지보수 피드백"(영어권: "feedback maintenance") 을 더블클릭합니다.
  - 개인정보(이름·경로·IP·MAC· hosts 주소)와 위험 코드(스크립트 태그· 실행 명령 등)를
    자동으로 지운 사본을 바탕화면에 만듭니다. 진단에 필요한 상태/KB 번호는 남깁니다.
  - 그다음 "GitHub 에 자동 업로드할까요?" 라고 물어봅니다.
      · y (동의)   → GitHub Discussion 에 자동으로 올리고, 성공하면 피드백 파일을 지웁니다.
      · n 또는 Enter (비동의) → 올리지 않고 피드백 파일을 바탕화면에 남깁니다.
      · 업로드 실패 → 오류를 알려주고 파일을 남깁니다(나중에 다시 시도 가능).
  - v1.14.5 부터는 프로그램에 토큰이 동봉돼 있어 아무것도 입력할 필요가 없습니다.
    y 를 누르면 바로 업로드됩니다(동봉 토큰은 디스커션 쓰기 권한만 있는 최소 권한).
    동봉 토큰을 쓰지 않으려면 폴더의 feedback-token.txt 를 지우면 됩니다.
    이전 버전처럼 직접 입력할 때는 https://github.com/settings/tokens 에서
    "Generate new token (classic)" → repo 체크 → 생성된 토큰을 붙여넣으세요.
  - 실행 결과는 바탕화면의 "자동유지보수_피드백상태.txt" 에 적힙니다.
    (성공/실패/비동의, 업로드 주소, 오류, 지운 위험 코드 건수 — 덮어쓰기라 파일이 쌓이지 않습니다)
  - Discussion 주소: https://github.com/argenluna/maintenance/discussions

【새 버전 알림 / 업데이트 (v1.8.0)】 바탕화면 "자동 유지보수 점검"을 누르면
  GitHub 에 새 버전이 있는지 확인하고, 있으면 알림창이 뜹니다.
    · 현재 버전보다 몇 버전 뒤인지, 새로운 기능이 몇 가지 추가됐는지 알려줍니다.
    · "업데이트" → 설치 폴더의 업데이트 스크립트가 실행되어 자동으로 업데이트 됩니다.
      (내부적으로 새 ZIP을 받아 해시를 검증한 뒤, 설정·로그를 그대로 이어받고
       예약 작업과 바로가기만 새 폴더로 바꿉니다. 기존 폴더는 롤백용으로 남습니다)
    · "취소" → 지금 버전을 계속 씁니다.
    · "다시 알리지 않음" → 그 버전은 더 이상 알리지 않습니다. (더 높은 버전은 다시 알립니다)
  새 버전은 https://github.com/argenluna/maintenance/releases 에서도 직접 받을 수 있습니다.
  ※ 예약 자동 점검 때는 알림창을 띄우지 않습니다(사용자가 직접 열었을 때만).

【문제가 생기면】 바탕화면 "자동 유지보수 제거"(영어권: "remove maintenance") 를 실행하면 예약 작업과 바로가기가 지워집니다.
  더 자세한 내용은 README.md 를 참고하세요.
