# 자동 유지보수 업데이트 — 주간 예약표

> 작성: 2026-11-21. 이 파일은 **배포Slott 운영표**다. `feedback-token.txt` 와 달리 민감정보가 없으므로 커밋해도 된다.

## 운영 규칙 (사용자 확정)

1. **배포는 주 1회(토요일 04:00).** 슬롯은 미리 한 주씩 예약해 둔다.
2. 내가 수시로 알려주는 변경사항은 **관련 조치끼리 같은 주 슬롯에 묶는다.**
   - 예: "표시/라벨 개선" 계열은 한 슬롯, "초보자 안내" 계열은 한 슬롯.
3. **묶을 만한 기존 슬롯이 없으면 이미 예약된 그 다음 주 슬롯에 넣는다.** (새 슬롯을 임의로 만들지 않음)
4. **만료 없는 피드백 토큰은 1개월 뒤(2026-12-21) 업데이트 항목에 함께 묶어 배포한다.**
   - 만료일이 있는 토큰은 넣지 않는다.
5. 버전 번호는 슬롯 순서대로 1개씩 올린다. 현재 최신 배포: **v1.14.8** (2026-11-21 우선처리 조기 배포 2건).
   - 예외: 2026-11-21 에 "보고서 자동 업로드 + 피드백 안내 + 뉴비 보고서"가 최우선 요청으로 들어와 주간 슬롯을 기다리지 않고 **v1.14.7 로 즉시 배포**함.
   - 같은 날 "A 선택 후 예약 실행도 자동 업로드 + 업로드 원본 버그" 추가 요청으로 **v1.14.8 로 즉시 배포**함. 이후 슬롯 번호가 밀림.
6. 실제 PC 반영은 예약 작업이 수행한다.
   - `OpenCode-Maintenance-AutoUpdate-Weekly` : 매주 토 04:00 (첫 실행 11/28)
   - `OpenCode-Maintenance-AutoUpdate-1Month` : 12/21 04:00 (토큰 포함)

## 예약 근거 (2026-11-21 조사)

이번 예약은 **실제 보고서 3건 + 인터넷 공식 문서/커뮤니티**를 대조해 정했다.

- **자료**: GitHub Discussion #6(RTX 5060 Ti), #7(RTX 5070 Ti) — 두 보고서 모두 공통으로 `UEFICA2023Status=NotStarted` + Secure Boot 비활성, 재부팅 대기(`PendingFileRename`), 이전 드라이버 다수 보류(7개/12개)를 보고함. 내 PC(Ryzen 9 5900X / RX 9070) 로컬 피드백은 잘못된 원본(`업데이트상태.txt`)을 읽어 점검 결과가 없었고, 이 버그는 v1.14.8 에서 수정됨.
- **W1 근거**: 보고서 #7 의 `GPU: Virtual Desktop Monitor (Error)` 라벨이 실제 GPU 인 것처럼 읽혀 가상 디스플레이임을 명시할 필요. WHEA Event 18 은 Ryzen 5000 계열에서 BIOS/칩셋 드라이버/PSU Idle Control 과 관련된다는 AMD 포럼·Microsoft Q&A·커뮤니티 다수 보고가 일치.
- **W2 근거**: Microsoft 공식 문서(`Update Secure Boot Certificates for Windows Devices`, `Secure Boot playbook for certificates expiring in 2026`) — 2011 인증서 2026-06~10 만료, 탐지 신호로 **이벤트 1801 / 1795 / 레지스트리 `UEFICA2023Status`** 를 제시. 현재 키트는 레지스트리만 확인하므로 이벤트 로그를 보완. 미갱신 시 BitLocker 복구 프롬프트·부팅 실패 위험 명시.
- **W3 근거**: 두 보고서 모두 이전 드라이버 7개/12개가 "예약 실행이라 확인 불가"로 계속 보류됨. 안전 원칙(자동 삭제 금지)은 유지하되 안내를 구체화.
- **이미 구현되어 있어 예약하지 않은 것**: DISM/RestoreHealth, mdsched 메모리 진단, SMART 디스크 검사, 네트워크 메트릭, 마스킹/PC 구분, 초보자용 결과표. 인터넷에서 흔히 요구되는 항목이지만 이미 들어가 있음.

## 분류 기준 (관련 조치 묶음)

- **검사 결과 표시/라벨**: GPU, WHEA, 상태 문구, 초보자용 결과표 기호 등 결과 화면에 보이는 것
- **초보자 안내**: newbie.txt, 결과표 비유, 질문·설명 문구
- **안전/삭제**: 삭제 확인, 목록 표시, 마스킹, 되돌리기
- **전송/토큰**: 피드백 업로드, 토큰, OAuth — ★ 만료 없는 토큰만 M1 에 묶음
- **예약/설치**: 스케줄 태스크, installer, 업데이트 스크립트
- **성능/안정성**: 드라이버, 디스크, SFC/DISM 등 실제 점검 동작

## 작업 순서 (매주)

1. 사용자에게 받은 항목을 위 분류 기준으로 분류 → 해당 슬롯에 추가 (없으면 다음 빈 슬롯).
2. 그 주 슬롯에 묶인 항목만 구현 → VERSION 올림 → 검증 → 빌드 → Release.
3. Release 후 이 표의 상태를 `배포됨` 으로 갱신.
4. 12/21 M1 에는 토큰이 만료 없는지 다시 확인한 뒤 함께 배포.
